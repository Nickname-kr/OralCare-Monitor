# OralCare Monitor · Phase 3.1

모바일 촬영 부위 선택 UI와 브라우저 내부 저장 복원 기능을 개선한 버전입니다.

## 3.1 주요 변경

- 큰 부위 선택과 세부 위치 선택을 서로 다른 화면으로 분리
- 큰 부위 카드를 누르면 즉시 세부 위치 화면으로 이동
- 세부 위치 화면에는 큰 해부학 그림 하나와 텍스트 선택 버튼만 표시
- 입술, 입천장, 볼, 잇몸, 혀, 입바닥, 어금니 뒤, 목 안쪽에 서로 다른 SVG 그림 사용
- 모든 해부학 그림을 400×300 고정 viewBox와 4:3 비율로 제작
- 작은 카드 안에서 그림이 늘어나거나 눌리지 않도록 `object-fit: contain` 적용
- 혀는 윗면, 아랫면, 왼쪽 옆면, 오른쪽 옆면을 별도 그림으로 제공
- 세부 위치 선택 전에는 하단 버튼을 숨기고 선택 후에만 표시
- iPhone Safari의 `100dvh`, safe area, 하단 버튼 겹침 보정
- 프로필을 localStorage와 IndexedDB 설정 저장소에 이중 저장
- localStorage 프로필이 사라져도 기존 사진 기록의 환자번호로 복구
- 가능한 브라우저에서 `navigator.storage.persist()`를 요청
- 사진 저장 후 IndexedDB에서 다시 읽어 실제 저장 여부 확인
- 기존 Phase 3 IndexedDB 기록을 유지하면서 DB 버전을 2로 업그레이드

## GitHub Pages 적용

기존 저장소의 파일을 이 프로젝트의 파일로 교체하고 `assets` 폴더도 함께 업로드합니다.

```text
index.html
style.css
app.js
README.md
assets/anatomy/*.svg
```

업로드 후 `Commit changes`를 누릅니다. 이전 화면이 캐시에 남으면 다음처럼 버전 값을 붙여 접속합니다.

```text
https://사용자명.github.io/저장소명/?v=3.1
```

## 권장 테스트

1. 기존 환자번호와 기록이 홈에서 복원되는지 확인
2. 촬영 부위 선택 화면에서 8개 그림이 서로 다르고 찌그러지지 않는지 확인
3. 혀 선택 후 별도 세부 위치 화면으로 이동하는지 확인
4. 세부 위치를 누를 때 큰 그림의 강조 영역이 바뀌는지 확인
5. 세부 위치 선택 전에는 촬영 가이드 버튼이 보이지 않는지 확인
6. 저장 후 Safari를 닫았다 다시 열어 기록이 남는지 확인
7. 전면 카메라 미리보기와 저장 사진의 좌우 방향 확인

## 로컬 저장의 한계

3.1은 여전히 서버 저장 방식이 아닙니다. 브라우저 데이터 삭제, 기기 교체, 시크릿 모드, 운영체제 저장 공간 정리로 기록이 사라질 수 있습니다. 장기적인 실제 서비스에는 서버 저장 또는 4차 백업·복원 기능이 필요합니다.
