# OralCare Monitor · Phase 4

구강점막 병소의 반복 촬영, 기기 내부 저장, 기록 비교에 더해 **백업·복원, 의료진용 리포트, 원본 사진 내보내기, 기록 검색, PWA 설치**를 지원하는 GitHub Pages용 웹앱입니다.

## Phase 4 주요 기능

- Phase 3.1의 두 단계 촬영 부위 선택 및 실제 카메라 기능 유지
- 누락되었던 `assets/anatomy` SVG 28개 포함
- 전체 기록을 `.oralcare.json` 파일로 백업
- 백업 파일을 기존 기록과 병합하거나 전체 교체 복원
- 마지막 백업일과 백업 이후 변경된 기록 수 표시
- 기간·부위·사진을 선택한 의료진용 리포트
- 브라우저 인쇄 화면을 이용한 PDF 저장
- 리포트 HTML 파일 다운로드
- 원본 사진 개별 저장 및 지원 기기 공유
- 날짜·부위·증상·메모 수정
- 타임라인 기간, 기준 사진, 증상 필터
- 다음 촬영일 `.ics` 캘린더 파일 저장
- PWA 홈 화면 설치 및 앱 셸 오프라인 캐시
- 데이터 삭제 전 미백업 기록 경고

## GitHub 업로드 구조

압축을 푼 뒤 **아래 전체 구조를 저장소 최상단에 업로드**합니다.

```text
index.html
style.css
app.js
manifest.json
service-worker.js
README.md
assets/
  anatomy/
    lips.svg
    lips_upper.svg
    ...
  icons/
    icon-192.png
    icon-512.png
```

ZIP 파일 자체를 올리지 말고 압축을 푼 파일과 폴더를 업로드하세요.

## GitHub Pages 업데이트

기존 파일을 교체하고 `Commit changes`를 누릅니다. 캐시된 이전 버전이 보이면 주소 끝에 버전을 붙입니다.

```text
https://사용자명.github.io/저장소명/?v=4
```

서비스 워커 캐시가 남아 있다면 Safari의 해당 사이트 데이터를 지우거나 홈 화면 앱을 삭제한 뒤 다시 접속할 수 있습니다.

## PDF 저장

리포트 화면에서 `PDF로 저장/인쇄`를 누릅니다.

- PC/Android: 인쇄 대상에서 `PDF로 저장` 선택
- iPhone/iPad: 인쇄 미리보기를 두 손가락으로 확대한 뒤 공유 버튼 → 파일에 저장

## 백업 파일 주의

`.oralcare.json` 파일에는 환자번호, 임상사진, 증상과 메모가 포함됩니다. 공용 PC, 공개 클라우드 폴더 또는 GitHub 저장소에 업로드하지 마세요.

## 현재 저장 방식의 한계

Phase 4도 중앙 서버 동기화 방식은 아닙니다. 기록의 기본 저장 위치는 사용자의 브라우저 IndexedDB이며, 백업 파일로 별도 보존해야 합니다. 환자번호와 PIN을 이용한 서버 저장 및 의료진 대시보드는 Phase 5에서 연결하는 것이 적절합니다.
